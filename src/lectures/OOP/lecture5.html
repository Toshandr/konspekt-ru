5.1 Раннее и позднее связывание

Вернемся к рассматриваемому выше примеру с классами Point и Circle: мы говорили о том, для изображения и удаления окружности недостаточно родительских методов Point.Show() и Point.Hide(). Поэтому потребовалось написать новые, перекрывающие их методы Circle.Show() и Circle.Hide().

Теперь сравним между собой методы Circle.MoveTo() и Point.MoveTo() – они идентичны. При этом, к сожалению, если мы не будем перегружать метод MoveTo() в классе Circle, по экрану будет двигаться не окружность, а точка, так как при вызове метода Point.MoveTo() в данном случае будут вызываться методы Point.Show() и Point.Hide(). Именно поэтому мы вынуждены заменять функцию Point.MoveTo() на внешне полностью аналогичную функцию Circle.MoveTo().

Логика компилятора довольно проста: вначале он всегда ищет метод с нужным именем, определенный внутри текущего класса (то есть внутри Circle в данном случае). Затем, если метод с таким именем не будет найден внутри исходного класса, компилятор обращается к его родительскому классу (в данном случае к классу Point) и ищет требуемый метод там. Если метод будет найден, компилятор подставит в точку вызова функции адрес метода родительского класса. Если же в родительском классе искомый метод также не будет найден, компилятор будет вынужден подниматься выше в иерархии классов до тех пор, пока не обнаружит метод с указанным именем.

Принятие решения на этапе компиляции относится к так называемому механизму раннего связывания.

В процессе компиляции программы компилятор конвертирует каждую инструкцию программы в одну или несколько строк машинного кода. Каждой строке машинного кода присваивается собственный уникальный адрес. То же самое происходит и при обработке функций: когда компилятор встречает функцию, она конвертируется в машинный код и получает свой адрес.

Связывание — это процесс, который используется для конвертации идентификаторов (таких как имена переменных или функций) в адреса.

Раннее связывание означает, что компилятор может напрямую связать имя идентификатора (например, имя функции или переменной) с машинным адресом. Поэтому, когда компилятор встречает вызов функции, он заменяет его инструкцией машинного кода, которая сообщает процессору о том, как перейти к адресу функции.

Рассмотрим еще один пример. Добавим к описанным выше классам Point, Circle еще один класс-наследник класса Point с именем Rectangle, в который добавим два целочисленных поля lehgth и width, обозначающие длину и высоту прямоугольника. При этом переопределим в данном классе соответствующие методы Show(), Hide(), MoveTo(). Будем полагать, что унаследованные поля X и Y обозначают координаты левого верхнего угла прямоугольника.

Предположим, что при решении определенной задачи нам необходимо работать с парами однотипных объектов, отображая их на экране. В этом случае для того, чтобы нарисовать на экране две окружности или два прямоугольника, нам понадобится написать перегруженные функции следующего вида:

void showPair(const Circle& circle1, const Circle& circle2)
{
  circle1.Show();
  circle2.Show();
}
void showPair(const Rectangle& rect1, const Rectangle&
rect2)
{
  rect1.Show();
  rect2.Show();
}

Однако, при создании дополнительных наследников класса Point, для каждого из них мы вынуждены будем перегружать функцию showPair(). То же самое нам придется делать, если мы захотим отображать пару объектов разных типов, например, окружность и прямоугольник.

Поскольку все наши классы являются наследниками класса Point, логичнее поступить следующим образом – описать единственный экземпляр функции showPair(), который смог бы работать не только с объектами базового класса, но и со всеми объектами дочерних классов, вместо использования отдельных методов для каждого производного класса:

void showPair(const Point& obj1, const Point& obj2)
{
  obj1.Show();
  obj2.Show();
}

При этом использовать данную функцию можно было бы, например, следующим образом:

Circle circle1(0, 0, 1), circle2(5, 6, 10);
Rectangle rect1(-1, -1, 10, 20), rect2(2, 5, 1, 8);
showPair(circle1, circle2);
showPair(rect1, rect2);
showPair(circle1, rect1);

Однако, к сожалению, все три вызова функции showPair() отобразят на экране лишь по две точки, поскольку в каждом случае будет вызван метод

Show() базового класса Point.

Избавиться от описанных выше проблем помогает использование виртуальных методов, реализуемых с помощью механизма позднего связывания.

В языке C++ для реализации механизма позднего связывания используются указатели на функции. Вкратце, указатель на функцию — это тип указателя, который указывает на функцию вместо переменной. Функция, на которую указывает указатель, может быть вызвана через указатель и оператор вызова функции. Вызов функции через указатель на функцию также известен как непрямой (или «косвенный») вызов функции.

С точки зрения машинных инструкций позднее связывание менее эффективно, поскольку в этом случае присутствует «посредник» между процессором и функцией. Если при использовании механизма раннего связывания процессор может перейти непосредственно к адресу функции, то при использовании механизма позднего связывания процессор должен прочитать адрес, хранящийся в указателе, а затем только перейти к этому адресу. Этот дополнительный шаг и замедляет данный процесс. Однако преимущество позднего связывания заключается в большей гибкости этого подхода, так как решение о том, какую функцию следует вызывать, может быть отложено до запуска самой программы.

Таким образом, раннее и позднее связывание – это термины, относящиеся к этапу, на котором обращение к процедуре связывается с ее адресом: при раннем связывании – на этапе компиляции, при позднем связывании – на этапе выполнения программы.

5.2 Виртуальные функции

Виртуальные методы — это методы, которые, будучи описанными в классах-потомках, замещают собой соответствующие одноименные методы везде, даже в классах-предках, если они вызываются для объекта, принадлежащего классу-потомку.

О классе, содержащем виртуальный метод, говорят как о полиморфном классе. В чем же состоит преимущество полиморфных классов?

Самое главное заключается в том, что полиморфные классы допускают обработку объектов, тип которых неизвестен во время компиляции. Функции, описанные в базовом классе как виртуальные, могут быть модифицированы в производных классах, причем связывание будет происходить не на этапе компиляции (с помощью механизма раннего связывания), а в момент обращения к данному методу (с помощью механизма позднего связывания). Адрес виртуального метода известен только в момент выполнения программы. Когда происходит вызов виртуального метода, его адрес берется из таблицы виртуальных методов своего класса.

Виртуальные методы описываются с помощью ключевого слова virtual в базовом классе. Это означает, что в производном классе этот метод может быть замещен методом, более подходящим для этого класса. Объявленный виртуальным в базовом классе, метод остается виртуальным для всех производных классов. Если в производном классе виртуальный метод не будет переопределен, то при вызове будет найден метод с таким же именем по пути вверх по иерархии классов (то есть в базовом классе).

Перепишем нашу иерархию классов:

class Point
 {
 ...
 public:
 ...
 virtual void Show();
 virtual void Hide();
 void MoveTo(int newX, int newY);
 };
 ...
 реализация методов класса Point
 ...
class Circle: public Point
 {
 ...
 public:
 ...
   // без метода MoveTo()
 virtual void Show();
 virtual void Hide();
 };
 ...
 реализация методов класса Circle
 ...

Прежде всего, заметим, что в классе Circle нет метода MoveTo(), он наследуется из класса Point. При этом все вызовы используемых внутри функции MoveTo() методов Show() и Hide() будут осуществляться непосредственно из тех классов, чьи объекты инициировали эти вызовы, так как методы Show() и Hide() являются виртуальными методами. При вызове метода Point.MoveTo() будут вызываться методы Point.Show() и Point.Hide(), а при вызове метода Circle.MoveTo() будут вызываться методы Circle.Show() и Circle.Hide(). И в случае, если будет вызван метод MoveTo() для объекта класса Circle, по экрану будет перемещаться окружность, как и было задумано.

По сути, виртуальная функция в языке С++ — это особый тип функции, которая при её вызове выполняет «наиболее» дочерний метод, который существует между базовым и производными классами. Метод производного класса вызывается тогда, когда совпадает его сигнатура (имя, типы параметров и признак того, является ли метод константным) и тип возвращаемого значения с сигнатурой и типом возвращаемого значения метода базового класса. Такие методы называются переопределенными методами.

Пожалуй, самое большое преимущество виртуальных функций – возможность структурировать код таким образом, чтобы новые дочерние классы автоматически работали со старым кодом, без необходимости внесения изменений со стороны программиста.

Вернемся ненадолго к разговору о функции, с помощью которой мы хотели отображать пары различных геометрических объектов на плоскости. Теперь, сделав метод Show() виртуальным, мы можем быть уверены, что данная функция правильно отобразит переданные ей в качестве параметров объекты:

void showPair(const Point& obj1, const Point& obj2)
{
  obj1.Show();
  obj2.Show();
}

В заключении еще раз напомним о том, что механизм позднего связывания, лежащий в основе подхода с использованием виртуальных функций, не эффективен. Обработка и выполнение вызова виртуального метода занимает больше времени, чем обработка и выполнение вызова обычного метода. Кроме того, компилятор также должен выделять один дополнительный указатель для каждого объекта класса, который имеет одну или несколько виртуальных функций. Поэтому использовать данный подход нужно довольно аккуратно и только в случае необходимости.

5.3 Применение виртуальных функций при использовании указателей

при использовании указателей на базовые классы

Область применения виртуальных функций не ограничивается случаями, аналогичными представленным выше. Другая сфера приложения виртуальных функций связана с использованием указателей на объекты. Особенность указателей в C++, напомним, состоит в том, что указатель, объявленный в качестве указателя на базовый класс, также может использоваться в качестве указателя на любой класс, производный от данного. В этом случае справедливы следующие присваивания:

Point pointObj(100,20);         // объект базового класса
Circle circleObj(20,30,10); // объект производного класса
Point *pointPtr;             // указатель базового класса
pointPtr = &pointObj;
                   // указывает на объект базового класса
pointPtr = &circleObj;
               // указывает на объект производного класса

Поскольку через указатель на объект можно вызывать метод этого объекта, то следующая запись вполне правомерна:

pointPtr = &circleObj;
pointPtr->MoveTo(10,10);

Однако наибольший интерес представляет вызов виртуальных методов с использованием этого указателя:

pointPtr = &pointObj;
pointPtr->Show(10,10);
            // вызов Show() объекта pointObj класса Point
pointPtr = &circleObj;
pointPtr->Show(10,10);
          // вызов Show() объекта circleObj класса Circle

Посмотрим, как этот механизм может быть нам полезен. Рассмотрим некоторую процедуру JumpFigure(), имитирующую «скачок» некоторого объекта на экране на заданную высоту h.

void JumpFigure(Point* AnyFigure, int h)
 {
 int oldX = AnyFigure->GetX();
 int oldY = AnyFigure->GetY();
 delay(100);             // временная задержка на 0.1 сек
 AnyFigure->MoveTo (oldX, oldY-h);            // «прыжок»
 delay(100);             // временная задержка на 0.1 сек
 AnyFigure->MoveTo (oldX, oldY);   // на исходную позицию
 }

Функции JumpFigure() можно передавать указатель на любой объект типа Point, либо на объект класса, порожденного из класса Point.

Как функция JumpFigure() узнает, объект какого класса фактически был передан ей? Во время компиляции программы – никак. JumpFigure() только делает ссылку на идентификаторы, определенные в классе Point. Благодаря наследованию, эти идентификаторы определены также и в любом классе, порожденном классом Point.

Методы GetX(), GetY(), Show() и MoveTo() фактически присутствуют в классе Circle так же как и в классе Point, и будут присутствовать в любом будущем классе, определенном в качестве потомка как класса Point, так и класса Circle.

Методы GetX(), GetY() и MoveTo() – статические методы. Это означает, что JumpFigure() знает адрес каждой процедуры еще во время компиляции. С другой стороны, Show() – это виртуальный метод. Есть различные реализации Show() для Point и для Circle, и JumpFigure() не знает во время компиляции, какая реализация будет использоваться.

В итоге, когда функция JumpFigure() вызывается, она ищет адрес правильной реализации метода Show() в таблице виртуальных методов класса, переданного в AnyFigure. Если экземпляр имеет тип Point, то вызовется Point.Show(), если это объект класса Circle, то Circle.Show(). Решение будет принято в момент вызова.

Подведем итог: теперь функция JumpFigure() может изобразить объект любого класса, порожденного классом Point, независимо от того, существовал ли данный класс при компиляции функции JumpFigure() или нет.

5.4 Виртуальные деструкторы

Как было отмечено ранее, при выходе из области видимости статических объектов производного класса автоматически происходит вызов деструкторов производного и базового классов в соответствующем порядке. Однако в случае, если объект производного класса создается динамически и разрушается с помощью указателя на базовый класс, вызов собственного деструктора для объекта не произойдет, что приведет к потере (не высвобождению) соответствующей области оперативной памяти, принадлежащей уникальным полям объекта, относящимся к производному классу. Рассмотрим следующий пример:

#include <iostream>
class Base
{
public:
    ~Base()
    {
        std::cout << "Calling ~Base()\n";
    }
};
 class Derived: public Base
{
private:
    int* m_array;
public:
    Derived(int length)
    {
    m_array = new int[length];
    }
    ~Derived()
    {
        std::cout << "Calling ~Derived()\n";
        delete[] m_array;
    }
};
int main()
{
    Base *base = new Derived(5);
    ...
    delete base;
    return 0;
}

Поскольку base является указателем на Base, при его использовании для удаления объекта класса Derived осуществляется проверка, является ли деструктор класса Base виртуальным. Поскольку это не так, предполагается, что должен быть вызван только деструктор класса Base. В результате при выполнении программы будет выведено следующее сообщение:

Calling ~Base()

При этом память, выделенная в программе под массив m_array, освобождена не будет.

Замечание. При попытке скомпилировать приведенный фрагмент кода некоторые компиляторы могут предупреждать об использовании не виртуального деструктора базового класса.

Для того, чтобы при удалении объекта класса Derived сработал деструктор этого класса (который, в свою очередь, вызовет деструктор класса Base), необходимо объявить деструктор базового класса виртуальным:

#include <iostream>
class Base
{
public:
    virtual ~Base()
    // виртуальный деструктор базового класса
    {
        std::cout << "Calling ~Base()\n";
    }
};
 class Derived: public Base
{
private:
    int* m_array;
public:
    Derived(int length)
    {
    m_array = new int[length];
    }
    ~Derived()
    {
        std::cout << "Calling ~Derived()\n";
        delete[] m_array;
    }
};
int main()
{
    Base *base = new Derived(5);
    ...
    delete base;
    return 0;
}

При выполнении программы на этот раз будет получен следующий результат:

Calling ~Derived()
Calling ~Base()

Отметим, что без необходимости не нужно создавать пустой деструктор производного класса только для того, чтобы пометить его как виртуальный. Как и в случае с обычными виртуальными функциями-членами, если деструктор базового класса является виртуальным, все деструкторы производных классов будут считаться виртуальными независимо от того, указаны ли они явно как таковые.

5.5 Динамическое приведение типов

На практике довольно часто возникают ситуации, при которых в коде программы представлен указатель на базовый класс, и при этом требуется получить доступ к данным, которые содержатся только в одном из производных классов. Рассмотрим следующую систему классов:

class Animal
{
private:
string name;
public:
Animal(string Name):name(Name){}
string getName()
{
return name;
}
virtual void makeSound()
{
cout << "Какой-то звук " << '\n';
}
};
class Cat : public Animal
{
public:
Cat(string Name):Animal(Name){}
void makeSound()
{
cout << "Мяу-мяу\n";
}
void leakMilk()
{
cout << "Лакаю молоко\n";
}
};
class Dog : public Animal
{
public:
Dog(string Name):Animal(Name){}
void makeSound()
{
cout << "Гав-гав\n";
}
void serve()
{
cout << "Служу хозяину\n";
}
};

Класс Animal содержит один виртуальный метод makeSound(), который переопределяется в дочерних классах, и метод getName(), который наследуется дочерними классами. Производные классы Cat и Dog содержат по одному собственному методу leakMilk() и serve() соответственно, определяющему некоторое специфичное поведение объектов данных классов.

В этом случае, проинициализировав указатель на базовый класс адресом объекта какого-либо дочернего класса, мы не сможем вызвать с помощью этого указателя методы, определенные в дочернем классе. Например:

Animal* dogAnimal = new Dog ("Шарик");
dogAnimal->serve(); // ошибка – класс Animal не содержит
// метод serve()

Одним из способов решения данной проблемы является добавление виртуальной функции serve() в класс Animal (чтобы в дальнейшем иметь возможность использовать переопределение данной функции для объектов класса Dog). Однако, при таком подходе мы будем загромождать класс Animal тем содержимым, которое должно быть интересно исключительно классу Dog, при этом к классу Cat этот метод вообще не имеет отношения. Аналогичные рассуждения применимы и к методу leakMilk() класса Cat.

В качестве альтернативного подхода язык С++ предлагает использование специального оператора, называемого оператором динамического приведения типа.

Напомним, в языке C++ существует возможность неявно конвертировать указатель класса Dog в указатель класса Animal. Этот процесс называется приведением к базовому типу (или «повышающим приведением типа») – ранее мы уже пользовались данным приемом. В частности, следующая строка из предыдущего примера

Animal* dogAnimal = new Dog ("Шарик");

для наглядности может быть заменена следующей парой операторов:

Dog* pDog = new Dog ("Шарик");
Animal* dogAnimal = pDog;

Однако, в языке C++ также существует и возможность обратного конвертирования указателя класса Animal в указатель класса Dog. С использованием подобного указателя мы могли бы решить возникшую проблему, вызвав напрямую функцию Dog::serve().

Данный процесс конвертирования называется приведением к дочернему типу (или «понижающим приведением типа»), и реализован данный механизм с помощью оператора динамического приведения типа dynamic_cast.

Синтаксически пример использования оператора dynamic_cast может выглядеть следующим образом:

type *subСlass = dynamic_cast <type*>(objPtr)

В треугольных скобках указывается тип данных, к которому необходимо преобразовать значение указателя objPtr, которое указано в круглых скобках.

Проверка корректности приведения типов производится во время выполнения программы. В частности, в случае, если осуществляется преобразование указателя, который содержит адрес объекта-родителя, к указателю типа объекта-потомка, в результате преобразования будет получен нулевой указатель.

Рассмотрим функцию main(), в которой будем использовать оператор dynamic_cast для приведения указателя класса Animal к указателям классов Dog и Cat:

void main()
{
Animal* dogAnimal = new Dog ("Шарик");
Animal* catAnimal = new Cat ("Мурзик");
cout << dogAnimal->getName() << endl;
cout << catAnimal->getName() << endl;
cout << endl;
Cat* cat = dynamic_cast <Cat*>(catAnimal);
if (cat)
{
cout << cat->getName()<< endl;
cat->makeSound();
cat->leakMilk();
}
cout << endl;
Cat* cat1 = dynamic_cast <Cat*>(dogAnimal);
if (cat1)
{
cat1->leakMilk();
}
else
{
cout << "Преобразование dogAnimal в Cat* невозможно"
<< endl;
}
Animal* animal = new Animal("Животное");
Cat* cat2 = dynamic_cast <Cat*>(animal);
if (cat2)
{
cat2->leakMilk();
}
else
{
cout << "Преобразование animal в Cat* невозможно"
<< endl;
}
}

Шарик
Мурзик
Мурзик
Мяу-мяу
Лакаю молоко
Преобразование dogAnimal в Cat* невозможно
Преобразование animal в Cat* невозможно

С помощью оператора dynamic_cast мы привели указатель catAnimal на Animal, с помощью которого был создан объект класса Cat, к типу указателя на Cat с именем cat. При этом вызов методов cat->makeSound() и cat->leakMilk() закончился успешно. Такое преобразование возможно, поскольку catAnimal содержит адрес объекта класса Cat.

А вот при попытке привести указатель dogAnimal на Animal к типу указателя на Cat с именем cat1 мы получим нулевой указатель, поскольку понижающее приведение типа указателя dogAnimal возможно только обратно в указатель Dog*.

Также мы получим нулевой указатель при попытке привести указатель animal, содержащий адрес родительского класса Animal, к указателю на

Cat.

Хотя во всех примерах, приведенных выше, мы применяли механизм динамического приведения типов к указателям (что является наиболее распространенным случаем), оператор dynamic_cast также может использоваться при работе и со ссылками.

Работа dynamic_cast со ссылками аналогична работе с указателями. Поскольку в языке C++ не существует «нулевой ссылки», то dynamic_cast не может возвратить «нулевую ссылку» при сбое. Вместо этого dynamic_cast генерирует исключение.

Animal* catAnimal = new Cat ("Мурзик");
Cat & cat = dynamic_cast <Cat&>(*catAnimal);
cat.getName();
cat.makeSound();
cat.leakMilk();
Cat& cat1 = dynamic_cast <Cat&>(*dogAnimal);
// в этом случае будет вызвано исключение

Отметим, что в некоторых случаях понижающее приведение типа с использованием оператора dynamic_cast не работает:

- при использовании модификатора наследования private или

protected;

- с классами, производными от классов, не содержащих ни одной виртуальной функции (и, следовательно, не имеющих виртуальных таблиц). В частности, в случае, если бы в приведенном выше примере мы удалили виртуальный метод makeSound() класса Animal, преобразование с помощью оператора dynamic_cast не выполнилось бы.

Как правило, применение виртуальных функций считается более предпочтительным вариантом по сравнению с использованием понижающего приведения типа. Однако в некоторых случаях все-таки стоит использовать механизм понижающего приведения типа:

- если нет возможности изменить родительский класс, чтобы добавить в него виртуальную функцию (например, если родительский класс является частью Стандартной библиотеки С++). Напомним, что при этом для того, чтобы использовать понижающее приведение типа, в родительском классе должны уже присутствовать виртуальные функции;

- если необходимо получение доступа к тем или иным методам, присутствующим только в производном классе;

- если добавление виртуальной функции в родительский класс не имеет смысла. В этом случае, в качестве альтернативы, можно также рассмотреть вариант создания абстрактного базового класса и использования чисто виртуальной функции, если нет необходимости создавать объект родительского класса.

5.6 Абстрактные классы

Иногда, когда виртуальная функция объявляется в базовом классе, она не выполняет никаких значимых действий. Это вполне обычная ситуация, поскольку часто базовый класс не определяет законченный тип, или объект базового класса не представляет особой ценности.

Вернемся к обсуждению примера с классами Point и Circle. В данном случае речь идет о том, что хотя родительский класс (Point) и содержит базовый набор методов и состояний, который производный класс (Circle) дополняет всем недостающим, полезность точки, как графического объекта, не велика, и, программируя, например, некоторый графический интерфейс, без точки в качестве объекта можно вполне обойтись. Однако мы выяснили, что именно класс Point как нельзя лучше подходит для роли базового класса, поскольку этот класс содержит в себе главные атрибуты любых графических объектов. Таким образом, мы приходим к пониманию того, что класс Point ценен не своими объектами, а своей способностью выступать в качестве базового класса, основы.

Заметим, что в этом случае, когда отпадает необходимость создавать объекты класса Point, виртуальные методы Show() и Hide() будут использоваться только в производных классах, где они в обязательном порядке должны будут быть переопределены. Для реализации данного подхода язык C++ поддерживает работу с чисто виртуальными методами.

Чисто виртуальные методы не определяется в базовом классе. У него нет тела, а есть только декларация о его существовании.

Для чисто виртуальной функции используется общая форма записи:

virtual тип имя_функции (список параметров) = 0;

Ключевой частью этого объявления является приравнивание функции к нулю.

Класс, содержащий хотя бы один чисто виртуальный метод, называется абстрактным классом. Абстрактные классы не бывают изолированными, то есть абстрактный класс всегда должен быть наследуемым. Поскольку у чисто виртуального метода нет тела, создать объект абстрактного класса невозможно.

Можно считать, что класс, специально определенный исключительно для обеспечения наследования его характеристик порожденными классами, и является абстрактным классом.

Вот как теперь станет выглядеть класс Point:

class Point
 {
 protected:
  int X;
  int Y;
  Boolean Visible;
 public:
  int GetX(void) {return X; }
  int GetY(void) {return Y; }
  Boolean isVisible() {return Visible;}
  Point(int newX =0, int new Y =0);
  virtual void Show() = 0;   // чисто виртуальная функция
  virtual void Hide() = 0;   // чисто виртуальная функция
 void MoveTo(int newX, int newY)
  {
  Hide();
  X = newX; Y = newY;
  Show();
  }
 };

Класс Point теперь действует как заготовка, из которого все порожденные классы могут взять элементы, общие для всех типов в иерархии, но теперь, при попытке создать объект типа Point, компилятор выдаст сообщение об ошибке.

Отметим, что необходимость создания конструктора класса при этом не отпадает, поскольку по-прежнему необходимо инициализировать переменные X, Y и Visible для дальнейшего использования их в производных классах.
